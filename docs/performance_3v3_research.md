# 单机版 3v3 科研模式：实测性能数据与优化方向

> 本报告基于**真实运行游戏**采样（非纯静态推算）。测试对象：单机 3v3（玩家 1 人 + 5 个 HELL AI）+ 科研模式 + 经典大陆 100×100。
> 测试机：Intel Core Ultra 9 285H + Intel Arc 140T 核显（16GB），游戏默认视口 **2400×1400**；Godot 4.7.2。核显机器是低端参考，独显机器绝对值会更高，但各项相对占比基本一致。

## 1. 测试方法

| 项目 | 做法 |
|---|---|
| 入口 | `godot --path . res://_perf_bench.tscn`，runner 自动设置 `ai_mode=3 / progression_mode=RESEARCH / HELL` 并进入 `rts_battle.tscn` |
| 规模 | 开局约 350 实体（60 军队），逐级直接刷兵到 **军队 80 → 150 → 220 → 300 → 380**，总实体 378 → **705** |
| 采样 | 每级稳定 1.5s 后采样 4~5s，FPS 用真实帧计数而非 `Engine.get_frames_per_second()`；记录 `frame_ms`、draw calls、primitives、节点/对象数 |
| CPU 归因 | 另跑 `--headless`（不渲染）同场景，得到纯 CPU 帧时间；并对 AI.decide、科研重算、迷雾、HUD 血条、实体缓存等函数**直接计时** |
| GPU 归因 | 把 `get_tree().paused = true` 暂停模拟（只剩渲染），逐项开关 SSAO / 阴影 / 水面平面反射 / 3D 分辨率缩放 / 隐藏全部实体，对比 FPS 与 draw calls |
| 脚本 | 根目录 `_perf_boot.gd`、`_perf_runner.gd`、`_perf_bench.tscn`；原始采样在 `_perf_out.json` 与各 `_perf_*.log` |
| 局限 | 单位是脚本直接刷出（不是自然运营到后期），相机固定在玩家出生点；4~5s 采样有 ±10% 噪声（同一配置两次基线 37.4 / 41.3 fps）；100×100 地图，3v3 大地图迷雾/寻路会更重 |

## 2. 实测总览

| 场景 | 军队数 | 总实体 | FPS | 帧时间 |
|---|---|---|---|---|
| 开局（未暂停，含渲染） | ~60 | ~350 | **40.7** | 24.6ms |
| 中期（未暂停） | ~220 | ~535 | **40.8** | 24.5ms |
| 后期（未暂停） | ~300 | ~615 | **33.3** | 30.1ms |
| 后期（未暂停） | ~378 | ~705 | **17.7~23.0** | **43~57ms** |
| 后期（暂停模拟=纯渲染） | 378 | 705 | **30.0~41.3** | 24~33ms |
| 后期（无头=纯 CPU，无渲染） | 370 | 697 | 51.2（60 上限） | **19.6ms** |

**拆开看**：后期一帧 ≈ CPU 19~20ms + GPU 24~27ms，两者叠加且部分串行，所以只有 18~23fps。
**结论**：单机 3v3 科研后期是 **CPU 与 GPU 同时吃紧**，不是单一瓶颈；要在核显上稳 60fps，必须两边各砍一半以上。

## 3. GPU：实测各项画质设置的成本（后期 378 军队，636 draw calls，1.16M primitives，暂停模拟）

| 配置 | FPS（两次采样） | 相对基线 | draw calls | primitives |
|---|---|---|---|---|
| 默认（画质锁死「极致」） | 37.4 / 41.3 | — | 636 | 1.16M |
| 关 SSAO | 46.9 / 41.5 | **+17%~19%** | 636 | 1.16M |
| 关实时阴影 | 51.5 / 46.4 | **+31%** | 378~393 | 0.77M |
| 关水面平面反射 | 46.3 / 44.4 | **+18%~25%** | 481~513 | 0.79~0.80M |
| 3D 分辨率 1.0 → 0.7 | 72.9 / 73.5 | **+85%~107%** | 636 | 1.16M |
| 全关 + 0.7 分辨率 | 89.8 / 92.5 | **+128%~161%** | 255 | 0.41M |
| 隐藏全部实体（地形/水面仍在） | 44.1 / 42.1 | +12%~19% | 137 | 1.05M |

实测结论：

1. **最大单项是渲染分辨率/填充率**：2400×1400 下核显先被填满，降到 0.7 分辨率帧率直接翻倍（+85%~107%）。这比「减少单位 draw call」有效得多。
2. **阴影第二**：+31%，且 draw calls 从 636 降到 ~390；当前默认 120m、4 分裂、所有模型强制投影。
3. **水面平面反射第三**：+18%~25%；它每帧把场景再渲染一遍（480×270 SubViewport，`UPDATE_ALWAYS`，`Ground.gd:3061-3079`）。
4. **SSAO 第四**：+17%~19%。单机场景 `rts_battle.tscn:34` 本来是 `ssao_enabled = false`，运行时被 `_apply_default_quality()`（`RTSBattleManager.gd:5144-5146`）强制改成 true。
5. **单位绘制不是主瓶颈**：把 700 个实体全部隐藏，draw calls 636→137，但 FPS 只涨 12%~19%。所以「每实体材质/draw call 爆炸」在单机模式下不是首因，**渲染分辨率 + 后处理/阴影/反射**才是。
6. **画质锁死的代价被实测坐实**：`hand_quality_mode=true` 让自适应降档完全不执行，玩家一直在最高档跑。

## 4. CPU：实测各系统耗时（无头模式，后期 370 军队/697 实体）

### 4.1 总体 CPU 随规模变化

| 军队数 | 总实体 | 无头 CPU FPS | CPU 帧时间 |
|---|---|---|---|
| 84 | 378 | 59.2（60 上限） | ≤16.9ms |
| 154 | 457 | 55.9 | 17.9ms |
| 221 | 526 | 55.5 | 18.0ms |
| 293 | 615 | 51.6 | 19.4ms |
| 370 | 697 | 51.2 | **19.6ms** |

60fps 预算只有 16.7ms，**约 150 军队开始 CPU 就超预算**；后期纯 CPU 已占掉 19.6ms，再叠加 24~27ms 的 GPU，就是实测的 43~57ms/帧。

### 4.2 子系统直接计时（后期，单次耗时）

| 系统 | 实测 | 频率/说明 |
|---|---|---|
| **AI.decide（5 个 AI 合计）** | **91~132ms（个别轮次 169~209ms）** | 单 AI 一次 **18~42ms**；任一 AI 进入决策的那一帧直接 +20~40ms，是主机最明显的卡顿尖峰 |
| **科研完成：给全部实体重算加成** | **33~42ms**（全部 6 家实体） | 真实一次完成只处理单玩家，约 6~8ms，加上生产列表刷新 + 全场景血条刷新，单次约 **10~20ms** |
| 实体缓存重建 | 0.6~1.0ms | 每 0.5s |
| 服务端迷雾全图刷新 | 0.4ms | 每 0.5s |
| Ground.apply_fog（地面迷雾贴图 diff） | 1.4~1.5ms | 每 0.5s |
| 实体可见性刷新 | 0.3~0.5ms | 每 0.5s |
| HUD 血条 `_update_health_bars` | 0.4~0.7ms/次 | 20Hz，约 8~14ms/s |
| 小地图数据构建 | 未单独测（每 0.5s 为每个实体建 Dictionary） | 次项 |

**实测 CPU 排序：AI 决策尖峰 > 科研完成尖峰 > HUD 血条 > Ground.apply_fog ≈ 缓存重建 > 迷雾/可见性。**
（AI 开/关对比实验因关闭 AI 后单位仍在执行已下发的寻路/战斗，未得到稳定差异；单次 decide 计时已足以定位尖峰。）

## 5. 对之前理论分析的修正

| 之前的推断 | 实测结果 |
|---|---|
| 每实体独立材质导致 draw call 爆炸，是客户端主因 | **单机不成立**：隐藏全部实体只 +12%~19%，draw calls 不是瓶颈 |
| 默认画质锁死影响大 | **成立且是最大项之一**：SSAO/阴影/反射/分辨率四项合计可让帧率翻倍以上 |
| AI 是 5 个，全实体扫描是 CPU 主项 | **成立**：单次 decide 18~42ms，是最大 CPU 尖峰 |
| 科研完成全实体重算造成尖峰 | **成立**：实测单次完成约 10~20ms |
| 迷雾每 0.5s 全图重扫是固定开销 | **偏小**：0.4ms + 地面 1.5ms，不是主因 |

## 6. 优化路线（按实测收益排序）

### P0 GPU（预计合计 +100%~150%，可把纯渲染从 ~25ms 降到 ~10ms）
1. **默认 3D 分辨率 0.8~0.85，并恢复自适应降档**：去掉 `_apply_default_quality` 的 `hand_quality_mode=true` 锁定（`RTSBattleManager.gd:1559,5134-5152`），从 level 1 起步；低端机自动降到 0.7（实测 +85%~107%）。
2. **阴影降级**：默认 60m/2 分裂；只有近处单位/建筑投影（实测 +31%）。
3. **水面平面反射**：低画质直接关闭，高档隔帧更新（实测 +18%~25%）。
4. **SSAO 默认关闭**，把场景原本的 `ssao_enabled=false` 还回去（实测 +17%~19%）。

### P0 CPU 尖峰（预计把后期 CPU 从 19.6ms 降到 ~12~14ms，消除 20~40ms 单帧卡顿）
5. **AI 决策分帧**：同一帧最多 1 个 AI 执行 decide；把 5 个 AI 的决策摊到不同帧（现有相位错峰不足以覆盖 20~40ms 的单次成本）。
6. **AI 共享世界统计缓存**：每 0.5s 生成一份按 owner 聚合的军队/建筑/敌方位置，替代 5 个 AI 各自的全实体扫描。
7. **科研完成优化**：按 uid 缓存加成结果 + 只遍历该玩家实体 + 血条脏刷新（单次 10~20ms → 2~4ms）。
8. 实体缓存/血条/迷雾已较小，可顺手降到 10Hz/2Hz，但不是关键。

### P1（继续压 CPU 固定成本）
9. 单机物理已会在 240 单位降到 30Hz（`RTSBattleManager.gd:5315-5331`），400+ 单位可再降到 25Hz。
10. 实体每帧 `_process`（回血/计时）合并到 5~10Hz 慢 tick。
11. HUD 血条 10Hz + 只处理屏幕内/受伤单位；小地图数组复用。

### 预期效果（基于实测线性外推）
- 只做 P0 GPU：后期纯渲染 ~25ms → ~10ms，整体从 ~20fps 到 **30~35fps**（CPU 仍占 ~14ms）。
- GPU + CPU 尖峰都做：后期帧时间可到 **16~20ms（50~60fps）**，核显机器上这是现实上限；独显机器会更高。

## 8. 已实施的优化与实测效果（2026-10-29）

已落地（本轮代码改动）：

1. **解除默认画质锁死**：`_apply_default_quality()` 不再设置 `hand_quality_mode=true`，默认从 1 档（3D 分辨率 0.85）起步，自动降档恢复生效。
2. **默认关 SSAO、阴影 70m + 2 分裂**（原来 SSAO 强制开、阴影 120m + 4 分裂）。
3. **默认关水面平面反射**（1 档 `set_water_quality(1)` 即关闭平面反射，低画质走屏幕空间近似）。
4. **AI 决策分帧**：`RTSBattleManager.acquire_ai_decide_slot()` 保证同一帧最多 1 个 AI 进入 `decide()`，其余 AI 顺延 0.1s，消除多 AI 撞帧的 100~200ms 尖峰。
5. **科研完成只刷该玩家的血条**：`_research_refresh_entity_bars(st)` 按 owner 过滤，不再全场景遍历。

优化后同一基准（378 军队 / 705 实体 / 暂停模拟做纯渲染）：

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 纯渲染 FPS（暂停模拟） | 37.4~41.3 | **60.9** | **+48%~63%** |
| 后期未暂停 FPS | 17.7~23.0 | **33.7~49.0** | **约 +1.6~2 倍** |
| draw calls | 636 | 418 | -34% |
| 显存占用 | 381MB | 303MB | -20% |

说明：纯渲染已从 24~33ms 降到 16.4ms，接近 60fps 预算；剩余瓶颈转为 CPU（后期仍约 19~20ms/帧），其中 AI 单次 decide 18~42ms 的尖峰尚未做「共享世界统计缓存」，是下一阶段重点。
